# 各个功能的实现说明

本文记录这个模块里每个功能**到底怎么实现的**，以及踩过的坑。设备：PLJ110 / ColorOS 17，
相机原来 7.006.121，2026-11-20 起换成 **7.016.29**（Reno 17 Pro 那份，作为 data app 更新装在
`/data/app/.../com.oplus.camera-.../base.apk`）。

## 0. 三层架构

| 层 | 谁 | 干什么 |
|---|---|---|
| hook 层 | 本模块（`com.oppocamera.unlock`，LSPosed） | 改配置返回值、hook 相机方法、注入面板、转发预览帧 |
| 文件层 | Magisk 模块 `oppo_camera_port` | 把 `/odm/etc/camera/*`、`/product/framework/*.jar`、`/odm/lib64/*.so` 这些**只读分区**上的资源换掉 |
| App 层 | 相机 APK 本身 | 7.016.29 的 unit.sdk 滤镜表与取帧类跟本机 resources 对得上，发布线用这一版 |

一句话：**能用配置解决的走 hook，只有文件能解决的走模块，只有换 APK 才能有的……就去换 APK。**

## 1. 调色盘（普通 / 二维）

- 数据：`basictone/palette/<SDR|HDR>/SC16Lut0..8`（16³ float32 三平面）+ `lmt/CWCM16Lut0..8`。
  `index = Sat档 × 3 + Cont档`，档 4 是 identity，9×9=81 格。
- 加载：`com.oplus.ocs.camera.CombineLutHelper.init(6 参)`，`arg[2]=setting`、`arg[5]=palette`。
  这台机器原厂没有 `palette/` 目录，强开会在 `libCombineLut` 里 `std::bad_alloc`。
- 实现：模块把 `assets/basictone` 部署到 `/data/user/0/com.oplus.camera/files/campalette/basictone`，
  再 hook `init` 把这两个路径参数换过去；`code != 0` 时用 odt 目录重试。版本戳 `.extract` 控制重铺。

## 2. Reno17 的调色盘资源为什么是 overlay

`/product/framework` 是 **overlay mount**：

```
overlay on /product/framework type overlay (ro,
  lowerdir=/my_product/product_overlay/framework:/product/framework)
```

所以「换 jar」必须绑**合并后的路径** `/product/framework/com.oplus.camera.unit.sdk.jar`；
绑 `/my_product/product_overlay/framework/...`（overlay 的层）**不生效**——开机时合并视图已经定型。
这一条踩过一次，记在这里。

## 3. 滤镜清单（琥珀 / 清透 / 胶片那一堆）

- 清单在 `com.oplus.camera.unit.sdk.jar` 的 `classes.dex` 里：一张
  「滤镜 id → `R.string.camera_filter_*`」的硬编码表。
  设备原版 91 处引用、无 `hu_po`；Reno17p 版 93 处、含 `hu_po`(琥珀)/`qing_tou`(清透)/`gt_*`。
- 模块把 Reno17p 的 jar（+ `oat/arm64/*.odex`、`*.vdex`）绑到 `/product/framework/`。
- 琥珀/清透还有第二道门（`FilterGroupManager`）：

```java
isSupportQingtouHupoFilter() = getConfigBooleanValue("com.oplus.feature.qingtou.hupo.filter.support")
initPaletteExtraFilterGroup(group) { if (isSupport...) { add("qing_tou.bin"); add("hu_po.bin") } }
```

  → hook `isSupportQingtouHupoFilter()` 返回 true。

## 4. 滤镜组全量放行

`FilterGroupManager` 有 32 个 `initXxxFilterGroup`，三层门控：

1. 静态字段 `sbXxxSupport`（clinit 按项目配置赋值）→ 反射置 true
2. `isXxx()` 静态判定 → hook 成 true
3. `getConfigBooleanValue(key)` 的 40 个 key → key 加进强制表

实测组大小：`initPaletteExtraFilterGroup=3`、`initUpdateBasicFilterGroup=23`、
`initUpdateSpecialFilterGroup=16`、`initUpdateFilmFilterGroup=13`…

**导演联名（姜文 / 贾樟柯）不放行**：`FILTER_SKIP` 里排除 `Director*`/`Jzk*`。

## 5. 胶片 / 实况滤镜（meishe_lut）

- 相机读 `/odm/etc/camera/meishe_lut` 的路径**硬编码在 native**（`/odm/lib64/libAlgoInterface.so`），
  Java 改不了 → 只能整目录 bind（模块 payload 135 个文件，原厂 95 + Reno17p 增量 40）。
- 新版 Java 会给 Meishe 设 `Custom LUT File Path` / `Custom LUT Factor` 两个参数，
  原厂 `libmsnativefilter.so` 没有这两个 paramId（日志刷 `Invalid paramId`，滤镜静默失效）
  → 模块把 Reno17p 的 `libmsnativefilter.so`（11.27MB，带这两个参数）也绑上，报错归零。

## 6. 不在本分支：实况调色盘 / POP 模式

「实况调色盘」= 独立拍摄模式 `retro_camera_mode`（资源 `camera_mode_retro_camera` 的中文值
就是 **"POP"**）。它需要动配置层和 native 侧，**这条发布线不带**，具体包括：

| 被摘掉的部分 | 位置 | 在哪条分支 |
|---|---|---|
| `retro` 相关 hook（模式工厂门 / cameraId 折回 / `za.s.b` 回落 / `Lut3dDataManager.e` guard / GL 反相遮罩 shader / retro 自绘 View） | `CameraPaletteModule.kt` | `main`、`backup/pop-wip-20261121` |
| `RETRO_KEYS` 强制放行（含鱼眼 key） | 同上 | 同上 |
| `camera_unit_config` / `camera_unit_feature_config.protobuf` 的 retro 补丁 | `magisk/post-fs-data.sh` + `payload/config/` | `main` |
| `basictone/setting_Retro/{SimTool_*.ini}`（四根滑杆的配置） | `app/src/main/assets/` | `main` |
| `touch enable_retro` 开关 | `magisk/service.sh` / `post-fs-data.sh` | `main` |

配置层现在保持**设备原厂文件不动**（整份换成 Reno17p 的会让人像模式预览冻结）。
POP 的完整证据链在 `CameraUnlock/_tools/dev/POP_CRASH_ROOTCAUSE.md`。

## 7. 鱼眼

鱼眼是 retro（POP）里的一个开关，不是独立模式（`com.oplus.camera.retro.filter.fisheye.enable` /
`com.oplus.camera.retro.fisheye.enable` / `com.oplus.retro.camera.max.zoom.value`，
LUT 图层是 `meishe_lut/fisheyelayer.rgba.bin`）。随 POP 一起移出本分支。

## 8. 灵感构图 / 灵感推荐

- 相机自带 AI 构图，但 feature 默认关：hook `CameraConfig.d(key)` +
  `FeatureConfigureAdapter#getFeatureInfoList` 把 `com.oplus.camera.feature.ai_composition` 补进特性表。
- **取帧**：预览帧由相机的取帧类提供。7.006 是混淆名 `wb.r` / `rb.t`；
  **7.016.29 换成了 `tb.q`**（方法 `f`，11 个参数、3 个 `HardwareBuffer`）。
  取帧类留了候选列表，按「方法名 f + 11 参」匹配。
- 取到的帧经 `AiBridge` 转给灵感构图模块（`com.linggan.goutu`），并用 `GyroTracker` 做跟踪锚点。
- **版本差异的坑**：装 7.016.29 后 `pb.b`（原 `InspirationAuthHeaderProvider` 的混淆名）消失，
  该类现在是非混淆名 `com.oplus.camera.feature.aicomposition.inspiration.network.core.*`，
  取帧类也改名 —— 表现就是「灵感构图/推荐失效」。

## 9. 鲜活 / 节日 / 庆典 开关

这三支的 LUT（`vibe.rgba.bin` / `festival.rgba.bin` / `ceremony.rgba.bin`）**本机和 Reno 固件里都不存在**，
所以做成开关、默认关：

- App 设置页开关 → `setprop persist.camunlock.filter.<name> 1`
- 模块读系统属性：`switchOn(name)`，据此决定是否 hook `isSupport*` / 设 `sb*` 标志 /
  `FilterGroup.addFrontAndBack` 里跳过对应的 LUT

## 10. 相机 APK 升级（7.016.29）

7.016.29 是调色盘 / 胶片那套接口对得最齐的一版（unit.sdk 滤镜表、`tb.q` 取帧类都在里面），
所以发布线用这一版。装法是普通 `adb install -r`（data app 更新），`/product/app` 里的原厂包不动，
随时可 `pm uninstall` 回滚。

## 11. 模块里装了什么（`oppo_camera_port`）

```
module.prop / post-fs-data.sh / service.sh / uninstall.sh / customize.sh
payload/
  apk/OplusCamera.apk + version.txt   ← 7.016.29 整包（172MB），开机补装
  apk_resources/                      ← 滤镜资源（原厂 95 → 135 个 LUT）
  framework/com.oplus.camera.unit.sdk.jar(+oat odex/vdex)  ← 滤镜清单（琥珀/清透）
  lib64/libmsnativefilter.so          ← 带 Custom LUT 参数的 Meishe 引擎
  lib64/libBasicTonePhoto.so          ← Reno 版（6 个 palette 符号，原厂 0 个）
  meishe_lut/                         ← 135 个胶片 LUT
```

- 配置层（`camera_unit_config` / `camera_unit_feature_config.protobuf`）**不替换**，保持原厂
- `service.sh` 开机等 `sys.boot_completed=1` 后比对版本，和 `payload/apk/version.txt` 不一致就
  `pm install -r -d -g`，日志在 `/data/local/tmp/cam_apk_install.log`
- 所有投递都是 **bind mount**，`/odm`、`/product` 原文件不动；`uninstall.sh` 里逐个 `umount` 即可回滚

## 12. 工具与坑

- 设备：KernelSU root；LSPosed（API 102）；`ksud` 管模块。
- **只能软重启**：`stop; start`，别用 `ksud soft-reboot`（那台机器上是真重启、掉 root）。
  更省的是 `sh /data/local/tmp/apply_all.sh` 手动重挂。
- **SELinux**：`/odm` 下的文件必须 `u:object_r:vendor_configs_file:s0`；`/product` 下是 `system_file:s0`；
  `/odm/lib64` 的 so 是 `same_process_hal_file:s0`。标签不对是**静默失效**。
- **`ksud module install` 更新已有模块** → 内容进 `modules_update/`，重启才换；就地更新用 `unzip -o`。
- **PowerShell `Set-Content` 会毁 UTF-8 源码**（变 GBK、丢换行、吞 `*/`）。源码只用编辑工具写。
