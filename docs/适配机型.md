# 适配其他机型 / 其他相机版本

这份文档是「换一台机器」或者「相机大版本更新」时的操作顺序。核心思路：
**所有会变的类名/混淆名都集中在候选表里，目标有没有命中都会写进 `adapt.log` 的自检表**，
适配就是照着 MISS 一项项补，而不是到处翻代码。

---

## 0. 先决条件

```sh
adb devices                          # 3B159C008AU00000 之类
adb shell su -c "id"                 # uid=0
adb shell "dumpsys package com.oplus.camera | grep -m1 versionName"
```

- KernelSU / Magisk root（这台机器是 exploit 注入，**整机重启会掉 root**）
- LSPosed 已启用 `com.oppocamera.unlock`，作用域勾「相机」
- 模块（`oppo_camera_port`）已刷入；只想最小替换时 `touch /data/adb/modules/oppo_camera_port/minimal`

---

## 1. 第一步永远是读自检表

```sh
adb shell su -c "sh /data/local/tmp/apply_all.sh"     # 或 stop; start
adb shell "am start -W -n com.oplus.camera/.Camera"
sleep 15
adb shell su -c "cp /data/user/0/com.oplus.camera/files/camunlock/adapt.log /data/local/tmp/"
adb pull /data/local/tmp/adapt.log
```

日志末尾会有一段：

```
===== CamUnlock 适配自检 开始 =====
模块：com.oppocamera.unlock 2.0.0 · 相机进程 pid=12345
设备（最终）：model=PLJ110 market=OPPO Find X9 · ColorOS=PLJ110_17.0.0.101(CN01) (API 37) · 相机=7.006.121
文件 胶片 LUT：琥珀：/odm/etc/camera/meishe_lut/hu_po.bin → 824183 B
文件 unit.sdk（滤镜清单）：/product/framework/com.oplus.camera.unit.sdk.jar → 5363803 B
适配自检：HIT 19 / MISS 1，耗时 88 ms
  HIT  camera.config      → d/getConfigBooleanValue hooked=2
  HIT  frame.source       → tb.q#f（11 参 / 3 个 HardwareBuffer）
  MISS inspiration.trace  → 候选都不存在：pb.b$a
===== CamUnlock 适配自检 结束 =====
```

**MISS 不是错误**，只是那一项功能不生效。适配就是把 MISS 变成 HIT。

> `persist.camunlock.log.dump 1` 打开后还会打印每个滤镜组的条目（显示名 + LUT），
> 验证「和光」这类重复、确认某支滤镜到底有没有进组，都靠它。

## 2. 第二步：照 MISS 补候选表

所有目标都登记在 `repo/app/src/main/java/com/oppocamera/unlock/hook/Adapt.kt` 与
`CameraPaletteModule.kt` 顶部。改的时候**只动候选/指纹，不动 hook 逻辑**。

| 自检 id | 找什么 | 在哪改 |
|---|---|---|
| `camera.config` | `com.oplus.camera.configure.CameraConfig` 的 `d(String,boolean,boolean)` / `getConfigBooleanValue(String)` | `CONFIG` 常量 |
| `camera.adapter` | `com.oplus.ocs.camera.config.FeatureConfigureAdapter` | `ADAPTER` |
| `combine.init` / `combine.sdk.init` | `CombineLutHelper` / `CombineLutProcessUnitSDK` 的 6 参 `init` | `COMBINE` / `COMBINE_SDK` |
| `filter.groups` / `filter.group.add` | `ipusdk.processunit.filter.list.FilterGroupManager` / `FilterGroup` | `FILTER_GROUPS` / `FILTER_GROUP` |
| `palette.gate` | `com.oplus.camera.common.utils.CommonUtil.isSupportPalette(String)` | `COMMON_UTIL` |
| `palette.color.table` | `ipusdk.processunit.filter.palette.PaletteSeekbarColorTable` | `hookPaletteColors` |
| `config.decrypt*` | `UpdateHelper.getConfigString(byte[], OplusStringJNI)` | `UPDATE_HELPER` |
| `frame.source` | **预览取帧类**（按「11 参 + ≥2 个 `HardwareBuffer`」匹配，不认类名） | `FRAME_CLASSES`：`tb.u / tb.q / tb.d / wb.r / rb.t` |
| `composition.entry` | 灵感构图入口（`runCompositionStreaming`） | `COMPOSITION_ENTRIES` |
| `inspiration.trace` | 灵感鉴权/网络类 | `INSPIRATION_CLASSES` |
| `producer.mode` | `producer.mode.ModeFactory#getMode(String)` | 常量写在 `hookProducerModeName` |
| `ui.skin` | `ImageView.setImageResource` / `View.setBackgroundResource`（系统类，基本不会 MISS） | 不需要改 |

参考：7.006.121 → `wb.r`（方法 `f`）；7.013.60 → `tb.u`（方法 `h`）；7.016.29 → `tb.q`（方法 `f`）。

**改完必须做的三件事**：编 APK → `pm install -r` → 重启相机 → 再看自检表，直到关键项 HIT。

## 3. 第三步：文件层（`/odm`、`/product`）核对

模块 payload 与目标机型的对应关系（`magisk_module/payload/`）：

| payload | 目标 | 用途 | 缺了会怎样 |
|---|---|---|---|
| `meishe_lut/`（135） | `/odm/etc/camera/meishe_lut` | 胶片 LUT（含琥珀/清透） | 滤镜条目在但没效果 |
| `apk_resources/` | `/odm/etc/camera/apk_resources` | 滤镜资源图/Lottie/视频 | 滤镜面板图标缺失 |
| `framework/com.oplus.camera.unit.sdk.jar` + `oat/arm64/*` | `/product/framework/…` | 滤镜清单（`camera_filter_*`） | 琥珀/清透等条目消失 |
| `lib64/libmsnativefilter.so` | `/odm/lib64/` | 带 `Custom LUT` 参数的 Meishe 引擎 | 日志刷 `Invalid paramId`，滤镜静默失效 |
| `lib64/libBasicTonePhoto.so` | `/odm/lib64/` | palette 相关符号 | 调色盘走 BasicTone 时异常 |

- 校验标签：`/odm` 下 `u:object_r:vendor_configs_file:s0`、`/product` 下 `system_file`、
  `/odm/lib64/*.so` 是 `same_process_hal_file`。**标签不对是静默失效**。
- `/product/framework` 是 overlay：只能绑**合并后的** `/product/framework/...`，
  绑 `my_product/product_overlay/framework` 不生效。
- 重复 `apply_all` 会叠挂载：`while mount | grep -q " $t "; do umount "$t"; done`。

## 4. 第四步：basictone 部署（调色盘的命门）

调色盘的 LUT 不在系统分区，而是由 LSPosed 侧部署到相机私有目录：

```
/data/user/0/com.oplus.camera/files/campalette/basictone/
├── palette/HDR|SDR/SC16Lut0..8   ← 来自模块 assets（本机原厂没有 palette）
├── setting/*.ini                 ← 来自模块 assets（含 SimTool_Palette_Photo_*.ini）
├── lmt/                          ← 从 /odm 递归拷（CWCM16 色彩矩阵）
├── odt/  setting_dolby/  vig/    ← 从 /odm 递归拷
└── .extract                      ← 版本戳（改了 assets 就 bump 它触发重铺）
```

要点：

1. **必须整份原厂 + palette**：`lmt`、`setting/Ditherout|FromXml|TriggerBIN`、`setting_dolby`、`vig`
   少任何一个都会让大师模式预览偏色/发灰。
2. `setting/*.ini` 只能用模块 assets 那份（原厂没有 `SimTool_Palette_*`，换原厂会
   `libCombineLutJni.processV3` SIGSEGV）。
3. **大师/专业模式默认不注入**（注入了会把 tone 打平、预览发灰，实测三个相机版本都一样）。
   要在大师里也能调色盘：`setprop persist.camunlock.palette.master 1`（会灰；
   7.016.29 相机必须开，否则 native 崩）。
4. 关掉注入排查：`persist.camunlock.palette.off 1` —— 原厂 7.006 不受影响，
   7.013/7.016 会崩，说明那两版必须有 palette。

## 5. 第五步：UI 换图（不替换 APK）

图标/引导图不用换 APK，运行时按**资源名**替换：

```
repo/app/src/main/assets/ui/
├── overrides.json    { "资源名": "文件名.png" }
└── *.png
```

- 生成：`python _tools/make_ui_assets.py`
  （数据来自 `_tools/extract_ui.py` 的对比结果：只收 `7.016 有改动/新增` 且**真的是图片**的
  `drawable`；shape/gradient 这类颜色 XML 不属于图片，换不了也不需要换）
- hook：`CameraPaletteModule.hookUiSkin()` 挂 `ImageView.setImageResource` 与
  `View.setBackgroundResource`，用 `resources.getResourceName(id)` 还原名字再查表。
  开关 `persist.camunlock.ui`（默认开）；`persist.camunlock.ui.trace 1` 会把相机每次请求的
  资源名记到日志（`UI 请求：…`），换机型时用它确认目标机的资源名是不是同一套。
- 换完重启相机，`adapt.log` 里应有：

```
HIT  ui.skin → hooked=2，映射 5 项：…
UI 资源就绪：filter_palette ← filter_palette.png（256x256）
UI 替换：filter_palette → filter_palette.png（第 1 次）      ← 进入对应面板时才出现
```

> 注意：相机若直接用 `<vector>`/canvas 自绘（例如调色盘入口），不会走上面两个入口，
> 这时只能靠 LSPosed 逐个面板 hook 或干脆不追新 UI。

## 6. 第六步：功能验证清单

| 检查 | 期望 | 怎么看 |
|---|---|---|
| 调色盘 LUT 加载 | `palette init code=0` | `grep palette init adapt.log` |
| 部署完整 | `.extract` = 当前版本戳、文件数 90+ | `cat …/basictone/.extract` |
| 滤镜组 | 19~32 个 `init*FilterGroup` 都 dumped，组内无重复显示名 | `persist.camunlock.log.dump 1` 后 grep `滤镜组` |
| 「和光」只一条 | 每组 1 次、`滤镜去重` 日志 4 条左右 | 同上 |

## 7. 常见坑（都踩过）

| 现象 | 原因 | 解法 |
|---|---|---|
| 相机点了没反应/回桌面 | 先分清：屏幕熄灭 / Activity 退出 / native 崩 | `dumpsys window \| grep mCurrentFocus`、`logcat \| grep "Fatal signal"` |
| `ksud soft-reboot` 后 root 没了 | 这机器上是真重启 | 只用 `stop; start` 或 `apply_all.sh` |
| bind 了但没生效 | SELinux 标签不对 | 按分区 `chcon`，见 §3 |
| 换 jar 没效果 | 绑到 overlay 的 lowerdir | 绑 `/product/framework/...` |
| 大师预览发灰 | 我们把 basictone 路径整体换掉了 | 默认大师不注入（§4.3） |
| 调色盘格子全黑 | `Recipe.empty()` 打桩 | 依赖类在就别打桩（本机 `ipusdk.PaletteSeekbarColorTable` 有） |
| 相机启动崩在 `processV3` | LUT 数组长度异常（setting/palette 缺件或版本不匹配） | 用「原厂整份 + palette」，别只换 palette |
| 模块重装后 0 个文件 | 旧 bind 指向被删的 payload | `post-fs-data.sh` 里先 umount 再 bind |
